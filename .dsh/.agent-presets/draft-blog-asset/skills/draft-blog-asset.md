# Draft Blog Asset

## Workflow
1. Clarify the target audience and useful angle.
2. Retrieve relevant wiki context as stable background knowledge.
3. Retrieve sources and notes as evidence for specific claims.
4. Build an outline internally before drafting; do not expose the outline or reasoning unless it is part of the requested document.
5. Produce an editable draft rather than claiming publication readiness.
6. Flag weak evidence, missing references, and claims requiring review.
7. Do not publish or save automatically.
8. Do not emit progress narration, tool commentary, or a completion message.

## Required Output
Return only the complete Markdown document. Start directly with one H1 title, use the required document H2 sections, and stop at the document's final line. Do not wrap the document in a Markdown code fence or add text before or after it.
