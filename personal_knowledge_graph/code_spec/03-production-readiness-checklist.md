# 生产上线自检清单

> 适用场景：FastAPI 后端服务、AI 应用、RAG 服务、Agent 服务上线前检查  
> 使用方式：发布前逐项确认，P0 未通过不得上线

---

## 1. P0 阻断项

### 安全与配置

- [ ] 没有硬编码 API Key、Token、密码、数据库地址、生产配置。
- [ ] `.env`、密钥文件、临时凭证没有提交到 Git。
- [ ] 生产环境配置来自环境变量或安全配置系统。
- [ ] CORS 只允许可信域名。
- [ ] 鉴权和权限检查已覆盖所有受保护接口。
- [ ] 日志和错误响应不包含密码、Token、Cookie、API Key、PII。

### API 与错误处理

- [ ] 所有外部输入经过 Pydantic 或等价 schema 校验。
- [ ] 错误响应格式统一。
- [ ] 不向客户端返回 Python 堆栈或内部异常细节。
- [ ] 错误码稳定、可搜索、可监控。
- [ ] 列表接口有分页和最大 `limit`。

### 数据库与一致性

- [ ] 数据库事务边界清晰。
- [ ] 重要写操作具备幂等设计。
- [ ] 用户输入没有拼接 SQL。
- [ ] 数据库 schema 变更有 migration。
- [ ] migration 已在测试环境执行验证。
- [ ] 大表变更已评估锁表、回滚和分阶段发布策略。

### 外部调用与异步

- [ ] 所有外部 HTTP 调用设置 timeout。
- [ ] 重试有最大次数、退避和抖动。
- [ ] 非幂等操作没有盲目重试。
- [ ] `async def` 中没有直接调用阻塞 IO。
- [ ] 批量并发有上限。

### AI / LLM

- [ ] 所有 LLM 调用设置 timeout。
- [ ] 模型输出进入业务逻辑前经过 schema 校验。
- [ ] 高风险动作没有完全由模型自然语言决定。
- [ ] 工具调用有参数校验和权限检查。
- [ ] RAG 内容不会覆盖 system prompt。
- [ ] Prompt、模型、参数版本可追踪。
- [ ] 日志没有记录完整敏感 prompt 或用户隐私原文。

---

## 2. P1 重要项

### 可观测性

- [ ] 请求日志包含 `request_id`、method、path、status、duration。
- [ ] 错误日志包含定位所需上下文。
- [ ] 慢请求日志已开启。
- [ ] `/healthz` 和 `/readyz` 可用。
- [ ] 关键指标已接入监控。
- [ ] 告警规则覆盖错误率、延迟、数据库连接、外部服务失败。

### AI 可观测性

- [ ] LLM 调用记录 provider、model、prompt version。
- [ ] 记录 input tokens、output tokens、latency、status。
- [ ] 记录模型失败率、重试次数、限流次数。
- [ ] 成本统计可以按用户、租户、任务聚合。
- [ ] 流式输出区分 completed、cancelled、timeout、error。

### 测试与 CI

- [ ] `ruff check .` 通过。
- [ ] `black --check .` 通过。
- [ ] `mypy` 或 `pyright` 通过。
- [ ] `pytest` 通过。
- [ ] 核心业务逻辑有单元测试。
- [ ] API 关键路径有集成测试。
- [ ] Bug 修复补充回归测试。
- [ ] 外部服务和模型调用在普通测试中已 mock。

### AI Eval

- [ ] 核心 AI 能力有最小 eval 集。
- [ ] Prompt 或模型变更已跑核心 eval。
- [ ] 线上失败案例已加入回归集。
- [ ] 结构化输出格式合规率达标。
- [ ] 安全攻击样例已覆盖。

---

## 3. P2 建议项

### 性能与容量

- [ ] 数据库连接池配置符合服务副本数和数据库连接上限。
- [ ] 高频查询已检查索引。
- [ ] N+1 查询已排查。
- [ ] 大文件上传下载使用流式处理。
- [ ] 缓存命中率和失效策略已评估。

### 发布与回滚

- [ ] 发布步骤可重复执行。
- [ ] 数据库 migration 有回滚或补偿方案。
- [ ] 涉及兼容性变更时有灰度或双写方案。
- [ ] 配置变更已在目标环境准备。
- [ ] 有明确回滚负责人和回滚触发条件。

### AI 成本与体验

- [ ] 单用户、单会话、单任务预算已配置。
- [ ] 预算超限行为明确。
- [ ] 高成本模型调用有条件限制。
- [ ] 超长输入有截断、摘要或拒绝策略。
- [ ] 缓存 key 包含 prompt version、model、参数和输入 hash。
- [ ] 缓存命中率有监控。

---

## 4. 上线后观察

发布后至少观察：

- [ ] 请求量是否异常。
- [ ] 错误率是否上升。
- [ ] P95 / P99 延迟是否恶化。
- [ ] 数据库连接池是否耗尽。
- [ ] 外部服务失败率是否上升。
- [ ] 后台任务是否积压。
- [ ] LLM 调用失败率是否上升。
- [ ] token 成本是否异常增长。
- [ ] 流式输出取消、超时、失败比例是否异常。
- [ ] 用户反馈和关键业务指标是否异常。

---

## 5. 回滚触发建议

满足以下任一条件时，应考虑回滚或降级：

- 错误率超过预设阈值。
- P95 / P99 延迟显著恶化。
- 出现数据丢失、重复扣款、越权访问等严重问题。
- 数据库连接池耗尽或核心查询异常变慢。
- 外部服务或 LLM 供应商不可用导致核心功能不可用。
- AI 输出出现高风险安全问题。
- token 成本异常增长且无法快速止血。

---

## 6. 最小上线标准

一个服务至少满足以下条件才建议上线：

- 配置和密钥安全。
- 输入校验完整。
- 错误响应统一。
- 关键日志和 request_id 可用。
- 外部调用有 timeout。
- 数据库迁移已验证。
- 核心路径测试通过。
- CI 通过。
- 有回滚方案。
- AI 功能有 schema 校验、timeout、基础 eval 和成本记录。
